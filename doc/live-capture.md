# 实时采集（界面操作说明）

接上分析仪**边抓边看**，不必先落成文件再打开。采到的报文与抓包文件走同一套
表格、筛选、详情、时间轴与导出 —— 实时与离线之间不该有一道需要重新打开的墙。

> **现状一句话**：界面这一整条链路已经能用（打开、连接、采集、筛选、详情、
> 时间轴、通讯日志、导出 CSV、停车、掉线），**设备层还没定**，
> 所以现在挂的是一个模拟设备源（`MockLiveSource`，约 8 条/秒的脚本化 PD 协商流程）。
> 换真设备要写的只有一个 `LiveSource` 实现 —— 界面与数据层都不用动，
> 见文末[「怎么接真设备」](#怎么接真设备)。

## 怎么打开

三个入口，落点是同一条命令 `connectDevice`：

| 入口 | 位置 |
| --- | --- |
| 顶栏插头图标 | 紧挨「打开文件」；悬停提示「连接设备，边抓边看（Ctrl+D）」 |
| 文件(F) → 连接设备… | 快捷键 **Ctrl+D**（macOS 为 ⌘D） |
| 空工作区空态 | 「打开文件」旁边的「连接设备」按钮 |

三条**都不是**「打开抓包的四种方式」里的一员：那四条本质都是「把一个路径变成一份文档」，
共用 `openFiles(paths)`；而实时采集**没有路径** —— 它是一次「连接」而不是「打开」，
硬塞进去只会让语义变浑。

**实时标签全局只允许一个。** 已经有实时标签时，再点上面任何一个入口都只是
**切回那一个**，不会新建第二个：一台设备只能有一个会话，两个实时标签会互相抢设备，
而且「哪个标签代表设备」会变得含糊。实时标签可以和文件标签同时开着，互不影响。

## 一次采集要走哪几步

| 状态 | 界面上是什么 | 你要做的 |
| --- | --- | --- |
| 未连接 | 中列空态：「这里还没有设备」+「查找设备」 | 点「查找设备」 |
| 正在查找设备 | 骨架行 + 转圈 | 等（约 0.8 s） |
| 已发现设备 | 设备卡列表，每张卡带能力徽章 | 选一个接口，点「连接」 |
| 连接中 | 选中的卡转圈，其余变淡 | 等 |
| 已连接（待机） | 设备卡 + 采集配置 + 两个动作按钮 | 勾好配置，点「开始采集」 |
| 零写监听中 | 一张只收不发的卡片，实时报条数 | 等它收完，或直接开始采集 |
| 采集中 | 状态条 + 报文表 + 实时曲线 | 看 |
| 已暂停 | 同上，状态条转黄 | 「继续」或「停止」 |
| 已停止 | 状态条转绿，数据转为普通抓包 | 筛选 / 导出 CSV /「重新开始」 |
| 已主动停车 | 整页横幅（红） | 读完原因，导出 CSV，或「断开设备」 |
| 设备已断开 | 整页横幅（红） | 「重新查找」 |

**开始采集之前，中列一直是连接面板；一开始采集就交回给表格** —— 那时用户最想看的是
数据，而不是连接界面。要回到连接界面，得先明确「断开设备」或「重新查找」
（不自动重连，见下文）。

### 采集配置

| 项 | 说明 |
| --- | --- |
| PD 报文 | 收 PD 报文 |
| 母线电压 / 电流 | 时间轴的主副曲线靠它 |
| 高速采样流 | 不是每个接口都能用 |
| 轮询节拍 | 20 / 50 / 100 / 200 ms 四档 |

至少勾一路数据才能「开始采集」。

**设备列表是按接口分的**，同一台机器的不同接口算两台（能力不同）。
**能力有三态：可 / 不可 / 未知**，而且不可用时**一定写出原因**，不是只置灰：

> 高速采样流 · 不可用 ——「该接口不支持设备认证，选了也采不到。换成接口 0 才能勾。」

「未知」和「不可」必须分开，理由与核心那边「未记录 ≠ 通过」是同一条：
拿 false 冒充未知，界面就会把「不确定」显示成「做不到」。

### 零写监听

**全程不向设备写任何字节**，只把设备打开收一段时间，报告收到多少条。
设备一打开就异常时，这是唯一不会让情况变坏的第一步。

## 状态条上的读数

采集期间状态条一直挂着，所有计数**都来自设备源的如实上报**：

| 读数 | 含义 | 什么时候变色 |
| --- | --- | --- |
| 报文 | 已入库的条数 | — |
| 速率 | 条/秒（用「条数 ÷ 时长」算**平均**，不是瞬时值） | — |
| 采样 | 母线模拟量点数 | — |
| 时长 | `mm:ss` | — |
| 丢包 | 队列溢出丢掉的条数 | **永远显示**（0 也是绿的），非 0 转红 |
| 超时 | USB 空闲超时次数 | 非 0 才出现，黄色 |
| 拒绝 | 设备明确拒绝的命令数 | 非 0 才出现，红色 |
| 已裁 | 因内存上限裁掉的最旧条数 | 非 0 才出现，黄色 |

三处刻意为之：

- **丢包 0 也要显示。** 它一旦非 0 会被误读成「设备没发报文」，所以「我们没丢」
  这个证据要一直在场。
- **超时非 0 属正常现象**（设备没话说时就会超时），所以用黄不用红；
  常年挂个 0 只会占地方，所以 0 时不显示。
- **拒绝非 0 即异常**，用红。

**内存上限 20000 条**（`kLiveRowCap`）。超出后从**最旧的**开始裁，并把裁掉的条数
记进「已裁」显示出来 —— 悄悄丢历史是不可接受的。

顶栏还会多一个 **CRC 未记录 N** 的 chip：**设备不保存 CRC**，
所以实时采集的 CRC 列一律留空，绝不因为「我们算了一遍对上了」就写 OK
（与 POWER-Z 分析仪那条路径同口径）。

## 采集中能做什么

数据一进来就都是普通报文了，所以离线能做的这里都能做：

- **报文表**：类型着色、方向徽章、告警标记照旧
- **自动跟随**：表格**在底部时**自动跟最新报文；**往上翻会自动停止跟随** ——
  往上翻就一定是在看历史，这时把你拽回最新一条是最讨厌的行为
- **筛选**：左栏全部可用，改完立刻生效
- **详情**：点一行看对象级解析
- **时间轴**：母线曲线实时长出来，标记、刷选、悬停读数照旧
- **导出**：见下节

## 底部区：两个模式

底部区（原先只放时间轴）现在是双模式，用头部的分段控件切换：

| 模式 | 内容 |
| --- | --- |
| 模拟量轨迹 | 时间轴，与文件抓包完全一样 |
| 通讯日志 | 原始命令往来：时间 / 方向 / 长度 / 字节 / 说明 |

通讯日志是排障时**唯一可信的原始证据** —— 命令究竟发出去了哪些字节、设备回了什么。
它**环形保留最近 256 条**（出问题一定发生在最近，而内存要有上界），
头部会显示「环形保留最近 N / 256 条」，另有「导出日志」与「清空」。

TX 用 accent 色、RX 用数据色，与时间轴主副曲线同一套配色。

文件抓包没有通讯日志，所以模式开关只在实时文档下出现。

## 导出 CSV

导出的入口和离线**完全共用**（顶栏导出菜单、外壳原生菜单、状态条上的「导出 CSV」
是同一段代码），四条语义定死：

| | |
| --- | --- |
| **导出什么** | 到**此刻为止的快照**。不是禁止导出，也不是非等采完 |
| **哪些行** | 跟随界面既有口径：菜单里的「导出 CSV（当前筛选结果）」导当前视图 |
| **文件名** | `实时采集-KM003C-20261004-0135.csv`（设备名 + 时间戳） |
| **导出后说什么** | 「已导出 1284 条（截至 151.9 s）—— 这是到此刻为止的快照，不是完整抓包」 |

两点不能省：

- **文件名带时间戳**，否则同一次采集里导第二次会把第一份覆盖掉。
- **提示语写明条数与截止时刻。** 采集中的导出注定不完整，而 CSV 交出去之后就没有
  上下文了 —— 别人拿到那个文件，无法从内容判断它是不是完整的抓包。
  这与「CRC 未记录就留空」是同一条原则：**不要把「不知道」伪装成「就是这些」。**

列名与核心 `csv.cpp` 逐字一致（13 列，PD 用 `Objects`、UFCS 用 `Bytes`），
CRLF、逐字段加引号、落盘带 BOM。

## 停车与掉线

两种情况都用**整页横幅**，不用弹窗 —— 弹窗会遮住表格，而此刻用户最想做的
恰恰是去看那些已经采到的报文。

**主动停车**（协议层异常，工具主动停并断开）：

- 原因原样写出来，例如「设备返回了一条无法解释的响应：cmd 0x41 · att 0x0002 ·
  长度 63 字节，超出了该属性的最大长度。」
- **无法解释的报文会先落表再停**，不丢弃 —— 它恰恰是排障时最需要看的
- 横幅说明「已采到的 N 条报文仍然完整可用」

**设备掉线**：横幅给出原因 + 「重新查找」。

两者共同的三条：

1. **不自动重连。** 要不要重来由人决定。
2. **不给「重连」按钮。** 只给「断开设备」/「重新查找」与「导出 CSV」——
   重连前必须先明确断开。
3. **不给「停止」「暂停」** —— 已经停了，再摆一个「正在跑」的操作只会误导。

## 演练：复现那两个难等的状态

「主动停车」「设备掉线」在真机上不好随时复现，但审查界面（尤其配色与文案）时必须看得到。
所以**只有模拟设备源**下会多出两个演练入口：

- **开始采集之前**：连接面板底部的「演练：主动停车 / 演练：设备掉线」
- **采集之中**：状态条上的「演练」菜单（采到数据之后再看停车横幅，才是真实观感）

真设备源接上后这些入口自动消失（判据是 `liveSource is MockLiveSource`）。

## 键位

| 键 | 作用 |
| --- | --- |
| `Ctrl+D` / `⌘D` | 连接设备（与文件菜单里那一项同一条命令） |
| `Ctrl+O` | 打开文件 |
| `Ctrl+W` | 关闭当前标签 |

**关标签会先把设备放出来**：关闭一个实时标签时，工作区会先「停止采集」
（**补发一次 Disconnect**）再断开、再移除标签，不是直接删掉完事 ——
少了这条，设备会一直停在「抓包中」的界面上，用户会以为工具把它扔下了。

> ⚠ **但关标签会丢掉已采的数据**，而且现在**没有二次确认**（见下节）。
> 想留着就先「导出 CSV」。

## 还没做的

按要紧程度排：

1. **真设备源。** 现在只有 `MockLiveSource`。协议层定了之后要写的是一个
   `LiveSource` 实现。
2. **退出应用时补发 Disconnect。** 现在**没有**这个钩子：直接关窗口时不会给设备
   发 Disconnect。真设备接上之前必须补上，否则设备会停在「抓包中」——
   这与「关标签要补发 Disconnect」是同一件事，只是路径不同。
3. **关闭采集中标签的二次确认。** 设计里定的是**两段式**：第一次点 × 只停止采集
   （并补发 Disconnect），再点一次才真关。**现在是一次就关**，所以会直接丢数据。
   两段式的好处是不用引入模态对话框（应用里目前一个 AlertDialog 都没有），
   代价是多一次点击，但那次点击有明确提示。
4. **命令行 `PDScope.exe --connect`**（开关参数本来就会被 `FilterOpenablePaths`
   当开关过滤掉，加它很便宜）。
5. **筛选与 CSV 是 Dart 侧的镜像。** `LiveSession.rebuildView()` 对应
   `core/src/filters.cpp`、`csvText()` 对应 `core/src/csv.cpp`。
   这是**当前的取舍不是遗漏**：实时数据在界面进程里，核心还看不见它。
   接入真协议后正确做法是把实时行喂进核心的 `Session`，让筛选与导出只剩一份实现。
   在那之前，改核心的筛选语义或 CSV 列名时**必须同步改这两个镜像**。

## 怎么接真设备

界面对设备源只认 `app/lib/core/live_source.dart` 里的 `LiveSource` 抽象：

```
enumerate()  枚举设备（含每项能力的三态 + 不可用的原因）
connect()    打开设备
listen(ms)   零写监听：收一段时间，一个字节都不写
start()      开始采集；之后按节拍往外发事件
pause() / resume()
stop()       停止采集 —— 收尾仍要发一次 Disconnect
disconnect() 断开并关闭句柄
events       事件流
```

事件有五种（`LiveRowsEvent` / `LiveBusEvent` / `LiveStatsEvent` /
`LiveTraceEvent` / `LiveStateEvent`）。接真设备时唯一要守的约定是：

**报文与详情要发成与核心 JSON 逐字段同形的 `Map`**
（字段名对齐 `core/src/session.cpp` 的 `packetListItemJson` / `packetDetailJsonOf`，
也就是 `app/lib/core/models.dart` 认的那套）。

守住了这条，`PacketRow` / `PacketDetail` / `PacketMarks` 全部原样复用 ——
界面因此不需要知道数据是文件来的还是设备来的。挂上新源只改一行：
`Workspace.openLive()` 里的 `MockLiveSource()`。

## 开发与验证

实时这一路**不碰 C 核心**（数据全在界面进程里），所以能脱离样本文件、脱离解码直接测：

```bash
cd app
flutter test test/live_test.dart      # 13 个用例
```

覆盖的是最容易在改动中悄悄坏掉、而手工点又容易漏的地方：

- 三个入口都落到 `openLive`，且**实时标签只允许一个**
- 连接面板 → 设备列表 → 待机 → 采集中 的状态推进，以及「中列什么时候交回表格」
- 状态条在、**丢包 0 也要显示**、主按钮是「停止」而不是「暂停」
- 暂停期间不再追加报文
- **时间轴头部里的模式开关能切到通讯日志、也能切回来**
- 停车横幅的标题、原因、「已采到的 N 条仍然完整可用」、以及**不给「重连」按钮**
- 掉线横幅与「重新查找」
- CSV 的 13 个列名、**CRC 未记录留空**、`filtered` 只导当前视图

> ⚠ 测试里最后要 `ws.closeAll()`（`_finish`）。采集中有两组活着的定时器
> （文档的 250 ms 刷新节拍 + 设备源的报文节拍），不关掉的话 widget test 会在拆卸时报
> 「A Timer is still pending」—— 那个报错指向测试尾部，跟真正的病因（谁没停）
> 完全不在一处。**不能用 `addTearDown` 代替**：框架的这项检查发生在测试体结束时，
> 而 `addTearDown` 在那之后才跑。

界面上的验收走实机：`artifacts/live-ui/` 下有各状态的实机截图。
